# Overlord Bridge 1.0.71

Groq key testing and inference now identify requests with an explicit Overlord User-Agent. The default Python urllib signature was being rejected by the provider edge security filter with HTTP 403 / Cloudflare error 1010, even for a valid saved key. A controlled comparison reproduced the default-client 403 and named-client 200; the repaired key test and a small live inference request both returned success without displaying credentials.

The setup window now distinguishes invalid-key HTTP 401 from access-denied HTTP 403. Security-filter code 1010 is explained accurately instead of asking the owner to recopy a valid key. Response bodies are not echoed into this diagnostic.

Regression tests use a local HTTP server to verify that both catalog GET and inference POST requests carry the same application identity, plus coverage for accurate, bounded 403 diagnostics.

Validation: 108 focused checks passed; canonical syntax/inventory, wheel and full offline suite passed (1,406 tests, two skips). Live corrected catalog GET and chat-completion POST both returned HTTP 200 using the saved owner key, without exposing it.
