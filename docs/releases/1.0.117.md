# Overlord 1.0.117

Windows worker PowerShell commands now return readable errors instead of
CLIXML. The previous -EncodedCommand host mode serialized errors and progress
records, which could push the actual error outside the 24,000-character
output tail. Silver's post-1.0.116 reports contain these serialized diagnostics.

The worker transports UTF-16 source as base64 through a fixed
-Command script-block invocation. Quoted strings, variables, newlines, separate
stdout/stderr, explicit exit codes and existing process cleanup are retained.
An appended exit maps the final PowerShell success status to the host's normal
0/1 result before leaving the script block; explicit exits keep their codes.
Ordinary CMD and direct Python execution are unchanged.

A Windows regression issues an error before 400 progress records. Previously
86,062 stderr bytes lost the diagnostic from the retained tail; the repair
returns 543 bytes with the diagnostic intact and exit code 7. Further tests
cover literal quotes, dollar signs, pipes, native stderr, multiline scripts,
implicit native/PowerShell failures, exceptions and recovery commands.
This is measured diagnostic preservation, not proof of project completion.
