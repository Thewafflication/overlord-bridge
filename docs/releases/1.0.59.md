# Overlord Bridge 1.0.59

- Remove copyable placeholder final answers from worker instructions and completion checkpoints. Describe the final-result fields while requiring the model to supply its own task-specific facts, validation and required commit details.
- Add a native finish_task tool, with final/outcome fields and a mechanical final alias. It submits the report to the existing completion reviewer, preserves matching tool-call/reply history after rejection and rejects mixed action/finish batches before executing any action. It does not create a project report file.
- Make final-report quality an explicit part of the LLM completion review, even when the recorded code work succeeded. A report-only rejection asks for a corrected summary using existing evidence, rather than unnecessarily directing the worker back into tool discovery.
- Recover an observed JSON terminal envelope using report plus an explicit finished/blocked outcome. It follows normal completion review and cannot turn a tool request into a final result. Malformed outcomes remain nonterminal instead of crashing the parser.
- Explain that passing tests validate their recorded assertions, including expected nonzero exits in subprocess error cases. Completion review must distinguish the test runner's successful exit from an error return expected by a test, instead of demanding unnecessary standalone repetition.

The live CSV CLI evaluation finished its implementation and local commit but returned the literal instructional placeholder as its final report. This patch fixes the prompting contract without regex-based classification of natural language replies. A regression covers rejecting and rewriting a placeholder after a read-only task, without repeating completed tool work.
