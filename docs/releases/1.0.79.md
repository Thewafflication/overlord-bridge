# Overlord Bridge 1.0.79

Standalone worker planning requests now mark explanation as required, nonempty in the provider-facing tool schema, matching the admission rule already enforced by Overlord. Previously the API advertised explanation as optional and then rejected replies that omitted it, repeatedly exhausting the planning phase. The correction applies only when update_plan is the sole available tool. Ordinary execution tools and caller-owned schemas remain unchanged, and missing or blank explanations are still rejected rather than invented.

Installed logs showed repeated missing_progress_explanation failures while all16scheduled runs eventually yielded at the1.0.78 stall limit. A native NVIDIA Nemotron Lightning synthetic planning probe reproduced HTTP200 without an explanation under the old schema; the corrected schema returned HTTP200 with a valid plan and nonempty explanation. Neither diagnostic executed project actions. This fixes the contradictory contract; external outages, quota limits and model noncompliance can still fail honestly under bounded retries.

Focused255tests passed, including schema parity for NVIDIA, Groq, Gemini and OpenRouter and preservation of normal execution schemas. Canonical tools/check.py all passed1,452tests with one skip. Installed verification follows signed deployment.
