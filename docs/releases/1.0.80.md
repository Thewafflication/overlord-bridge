# Overlord Bridge 1.0.80

Project Python selection now requires both the .venv interpreter and pyvenv.cfg. Previously a partially created environment could contain a Python launcher but no configuration; Overlord still selected it for direct Python and command PATH, making even bootstrap calls fail. Such environments now use the existing bridge interpreter as a bootstrap fallback without modifying the project. Selection is recalculated per call, so a repaired project environment is selected automatically. Startup/recovery guidance distinguishes this fallback from a ready project environment and advises keeping project dependencies local.

The observed Pydecipher run ended with No pyvenv.cfg file. A real isolated Windows fixture reproduced that exit106 using unchanged1.0.79 selection. With the fix, direct Python and python commands exit0 through fallback, leave the missing project config untouched, and then select the project interpreter successfully after the fixture configuration is restored. This is a configuration-presence check, not a full interpreter-health or dependency installer. Existing owner edits and environments are not automatically repaired, deleted or recreated.
