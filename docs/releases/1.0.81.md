# 1.0.81 — preserve existing owner files during free-worker cleanup

A worker deleted a pre-existing untracked binary with Python cleanup despite
explicit preservation instructions. Windows free workers now hold OS file
handles that prevent deletion, rename and replacement of existing allowed
uncommitted files, including initialized nested repositories. Admission fails
before model tools run if protection cannot be established completely.

Handles are released during worker cleanup, including cancellation and crashes.
In-place edits and removal of worker-created scratch files still work. The
guard reads no file contents, changes no ACLs and makes no backups. It cannot
recover earlier deletions or prevent arbitrary in-place overwrites; clean
committed files, ignored/generated or off-limits paths, links, other worker
brains and non-Windows systems are outside its scope.

Regression checks execute real Python and Windows PowerShell cleanup against
isolated fixtures and repeat the observed `run_python` deletion through the
actual WorkerManager lifecycle. See [the protection contract](../owner-file-protection.md).
