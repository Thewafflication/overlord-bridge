# Overlord 1.0.91

Fix Windows workers opening PowerShell scripts in the associated editor instead
of executing them. The observed command was
`cd <project> && .\tools\Get-LatexRuntime.ps1 -Offline 2>&1`.
The old protection only recognized a script at the beginning of the whole
command, so the script after `&&` reached CMD's file-association handling and
an editor launch could be reported as exit zero.

Ordinary CMD script command heads now use an explicit noninteractive PowerShell
process with `-File`. Quoted paths, arguments, chain operators, redirections,
CALL and command groups are preserved. Output and failure codes come from the
script execution. The tool result retains both the original command and the
executed command. Windows file associations and user settings are not changed.

The bounded CMD lexer does not convert arbitrary shell programs. Nested CMD,
IF/FOR/START forms involving `.ps1` require the existing explicit PowerShell
tool mode; they cannot fall through to file association. Literal script mentions,
explicit PowerShell commands and intentional editor commands remain unchanged.
Arbitrary Python subprocess launches are outside this command normalization.

Regression coverage includes the reported Get-LatexRuntime command shape using
an isolated script, paths/arguments containing spaces, successful and failing
scripts, conditional chains, quoting, redirections and rejected ambiguous forms.
