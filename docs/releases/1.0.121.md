# Overlord 1.0.121

Free coding workers now retain their last two execution requests and provider
responses under `worker_reports/requests`. Each capture identifies the worker /
project scope by a filename hash and records the run, action step, model and
timestamps. Planning, independent reviews and ordinary chat are excluded.

Capture occurs at the HTTP boundary **after provider-specific context fitting**.
The request includes messages and effective tool schemas; the paired response
includes the assistant message and finish reason, before tool execution or
response rejection. This allows inspection of whether source evidence was
present in the request preceding a repeated read. HTTP failures retain status;
transport failures retain only exception type. Cancellation propagates and can
leave a pending request. Pending does not establish a crash or process liveness.

Two fixed slots survive worker restarts and overwrite the oldest attempt. Each
file is capped at 256,000 UTF-8 bytes, including a 192,000-byte request budget
and 48,000-byte response budget. Oversized sections are replaced by explicit
omission metadata and a hash of the redacted section, never malformed JSON.
This is a rolling diagnostic window, not a complete run transcript.

Headers, provider URLs, authentication fields and provider error messages are
excluded. Source and model text use the existing environment-secret redaction
(values of at least eight characters in variables named TOKEN, KEY, PASSWORD
or SECRET). This cannot recognize every secret embedded in arbitrary source.
Captures contain project text like the existing project-memory archive and
should remain local. Linked capture storage is rejected. Diagnostic write
failures do not change provider results or retry behavior; owned IO finishes
before cancellation acknowledges idle.

Controlled tests cover fitted payloads, source-to-next-decision pairing,
restart retention, isolation, redaction, Unicode byte limits, storage failure,
transport failure and cancellation. This improves diagnosis, not project
completion. No accepted-delivery increase is established by these tests.
