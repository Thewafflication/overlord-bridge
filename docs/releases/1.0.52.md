# Overlord Bridge 1.0.52

- Detect stale local-control discovery when the bridge process has exited, including exit during a pending request. Return `control_unavailable` promptly and clean up pending files.
- Keep live, inaccessible, or reused PIDs subject to the normal instance-correlated acknowledgement. Process existence never confirms status or stop. Windows checks use a read-only query handle.
- Give status timeouts a status-specific explanation instead of the misleading stop message.

Regression checks cover a real exited process, exit while waiting, live/unknown PIDs, request cleanup and action-specific timeout messages.

Validation: canonical syntax/inventory, wheel build and full suite passed with 1,307 tests and two skips. All 11 local-control tests passed. Against the installed runtime, the client immediately identified stale discovery, then received matching live status and stop acknowledgements after the bridge restarted.

Final verification: Windows and Linux release CI passed. The signed package verified and installed successfully; its control module matches the tested source. Installed Python reported v1.0.52, rejected stale discovery for a real exited test process, and received live status/stop acknowledgements from the same bridge instance, which remained online and idle.
