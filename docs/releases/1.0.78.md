# Overlord Bridge 1.0.78

Free-worker provider waits now yield after three unavailable pool attempts or 600 seconds without a usable model response, whichever comes first. The wall-clock deadline includes model selection, pacing, capacity waits and in-flight network calls. Successful short waits still recover, and owner cancellation propagates normally. Provider quotas and cooldowns remain intact.

A worker that exhausts this budget reports stalled rather than completion, saves its original task, last plan and recent evidence with the terminal report, preserves checkout edits/commits and releases its scheduler slot. Planning, execution and completion-review requests all use this bound. Other scheduled projects can then proceed. A later run must reconcile existing work; this is not transparent restoration of the complete prior dialogue. This limit addresses provider failure cycles, not every possible valid-response discovery loop or incorrect completion judgment.

Observed failure: a website worker remained at its progress checkpoint while one model repeatedly timed out and another omitted required planning arguments. Its existing unlimited capacity wait kept other schedules blocked. Tests cover that mixed-provider failure, recovery, in-flight cancellation/deadline, all three worker phases, preserved file changes and subsequent scheduler dispatch.
