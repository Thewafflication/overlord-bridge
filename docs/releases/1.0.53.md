# Overlord Bridge 1.0.53

- Set UTF-8 standard streams for worker Python subprocesses, including Python invoked through `run_command`. Redirected Windows Python previously used the legacy code page, so Unicode output could crash a successful script or become replacement characters in tool results.
- Preserve both stdout and stderr and retain the command's actual exit status. The bridge's own environment is unchanged; the encoding policy applies to worker child processes.

Reproduced on Windows: printing `café 世界 🙂` through `run_python` failed with a cp1252 UnicodeEncodeError before the fix and succeeded with exact UTF-8 output afterward. Regression tests run both Python tool paths with an inherited cp1252 setting, Unicode on both streams, and success/failure exit codes.

Validation: canonical syntax/inventory, wheel build and full suite passed with 1,311 tests and two skips. The initial focused worker suite passed 98 tests; the full suite additionally covers both success and failure cases for each command path.

Installed verification: Windows/Linux release CI passed and the signed package installed successfully. The packaged worker matches the tested source. Both installed Python tool paths returned exact Unicode stdout/stderr with a successful exit even when the parent environment requested cp1252.
