# Overlord 1.0.99

Fix an observed ownership violation: a completion reviewer demanded commits for
four pre-existing Word-GPT helper scripts, and the worker staged and committed
them despite recognizing that they belonged to the owner. That local commit is
preserved for owner review and is not counted as delivered work.

Free workers now pin pre-existing untracked owner paths for execution and
completion review. Model command and Python tools hold a temporary cooperating
Git index lock. A single explicit add of owned file paths or a separate commit
can proceed; broad staging and pre-existing owner paths are rejected. Explicit
owner-queue publication paths remain authorized, including an existing harness
assigned for repair. Reviewers cannot turn unrelated dirty files into worker
ownership by demanding a clean tree. Read-only validation needs no commit.

The exact free-worker integration regression fails on 1.0.97 (the owner helper
enters the index) and passes with this change. Six additional Git-backed cases
cover owned commits, shell/Python indirection, existing locks, cancellation and
external staging. This verifies the reproduced failure, not a model intelligence
or project completion-rate improvement.

Scope: the lock protects the worker root's default Git index for the duration of
each model tool call. This is not an arbitrary-code sandbox: alternate indexes,
direct database writes, nested indexes and processes outliving the call remain
outside the contract. Existing owner data and history are not automatically
reverted. Free model admission and payment policy are unchanged.

1.0.98 was not installed: Windows CI found that the initial ownership notice could prevent constrained-input fitting under longer paths. 1.0.99 keeps the protected path list pinned in a compact notice; full reviewer ownership evidence and mechanical index checks remain. The long-path reproduction now passes without raising provider budgets. 1.0.98 is marked prerelease.
