# Overlord Bridge 1.0.75

/schedule edit <id> <task> updates an existing schedule's future task text while Overlord remains online. It preserves the ID, state, interval, due time and last dispatch, creates no duplicate schedule, and does not retarget a running worker. Console and Telegram use the same normal owner-command handler; editing needs no model call. Help and shared capability discovery document the command.

The monitoring workflow observed pydecipher repeatedly rediscovering the same failing case across539 steps. It could stop the loop, but could not feed the specific finding back into the existing live schedule without an offline file edit/restart or removing/recreating/resetting the schedule. Live task edits provide that missing feedback path. The monitor still audits rather than implementing project fixes, and low-quality model decisions are not treated as automatically solved by a prompt update.

Focused tests25 passed, covering all schedule states, persistence, busy/current versus future work, timing/identity preservation and failure atomicity. The old handler replay left the task unchanged; the repaired handler updates it without timing changes. Canonical syntax/inventory, wheel and full offline suite passed (1,430 tests, one skip). The existing local HTTP fixture now consumes and checks the synthetic POST body before responding; provider production code is unchanged. The combined focused schedule/HTTP checks passed27 tests. Installed workflow qualification is recorded separately.
