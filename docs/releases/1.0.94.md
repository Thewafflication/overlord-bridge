# Overlord 1.0.94

Ready owner queue entries now supply execution readiness. Workers still plan and
can report concrete blockers, but cannot downgrade a defined task because its
implementation or diagnosis has not happened. The new check_acceptance tool runs
actual owner checks on demand. Passing a probe cannot waive later completion or
publication checks.

The compact owner contract is pinned through context trimming. Large acceptance
implementations remain in the harness, reducing prompt pressure and preventing
contract loss. Optional stale handoffs and orientation can be trimmed.

Reports expose delivery_status, action_steps and readiness_source. The worker
outcomes CLI separates independently accepted work from model-reviewed finishes
and counts unique task IDs. See docs/overlord-improvements.md for the frozen
baseline, regression comparison, measurement procedure and live deployment results.

Free mode and its admitted model pool remain unchanged; no paid fallback is added.
