# Overlord 1.0.105

Add explicit read-only owner-file contracts for ready free-worker tasks. A
`protected_files` mapping names relative paths and exact SHA-256 baselines.
Windows mandatory sharing denies writes and deletion while the worker runs,
including clean tracked files; verification runs while locked, before any model
or acceptance-preflight action. Mismatches stop incomplete with zero model
actions and structured file diagnostics. Unsupported platforms fail closed for
this explicit contract. Other editable files retain the existing policy.

Four Pydecipher files no longer match their established owner hashes and now
match HEAD instead. Expected hashes remain unchanged. Known file history,
reflogs, unreachable commits and project-local source backups yielded no matching
original copies. The specific overwrite cause is not established. Pydecipher's
existing schedule is intentionally paused until original bytes are restored;
its ID and interval remain. The other 15 schedules stay enabled. This is a
documented safety exception to the normal 16-active inventory, not a lost
schedule or completed project run. Owner-provided originals/backups are needed.

Native child tests prove writes succeed under the old editable policy, fail
under explicit read-only protection, then work after cleanup. A worker test
rejects a changed baseline before any model call. This does not reconstruct
missing data or sandbox administrative bypasses.

CI now probes an actual headless Tcl interpreter first. When missing, it installs from signed official Ubuntu sources using a temporary APT source list, without changing runner mirror configuration or disabling signature checks, and probes again before the full test suite. This avoids the observed Azure mirror DNS dependency. Source verification follows [Ubuntu archive integrity guidance](https://documentation.ubuntu.com/security/software-integrity/archive-verification/). No tests are skipped to bypass provisioning. Candidate1.0.104 was not installed.
