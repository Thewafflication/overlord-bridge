# 1.0.125 - retain command evidence through context fitting

Actual Silver execution captures at steps 248 and 249 contain no recent paired
tool exchanges after source/SDK-probe batches. The fitter could shorten source
pages but left command output untouched, so an oversized command result could
evict its entire batch. The preceding full output was not retained; this is
an observed omission plus controlled reproduction, not an exact request replay.

Context fitting now shortens command results structurally alongside source
pages. Exit code, timeout status, success, interpreter/shell and other metadata
remain. Captured stdout and stderr keep marked beginning/end excerpts and explicit
truncation flags. Source cursors and paired calls/results survive. Commands and
original command strings can also be shortened with explicit flags. Credential
redaction precedes excerpting. Oversized tool-call arguments and protected
instructions retain the existing bounds and failure behavior.
Bytes already omitted by the subprocess capture are not recovered.

Command transport uses the same structure before falling back to generic JSON
tails. This avoids double-escaped output exceeding the transport limit or
dropping exit status and stderr. Three new regressions failed before the repair;
native and fallback batches now fit with command/source evidence intact. A
scripted worker consumes a real large subprocess result, edits and validates a
file. These checks establish harness behavior, not live model quality.

Post-1.0.124 baseline at 2026-11-18T06:03:17.942740Z: three terminal outcomes,
two stalled and one skipped, zero verified deliveries; one confirmed mutation,
143 distinct successful command results and 10,765.016 recorded worker seconds.
Live accepted-delivery improvement remains unproven. See the dated release
ledger for final checks, publication, installation and subsequent measurement.
