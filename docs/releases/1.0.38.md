# Overlord Bridge 1.0.38

- Explicit free coding-worker completion now receives a separate LLM review against the original task and bounded, redacted tool evidence. The reviewer checks requested work, successful validation, local commit and requested publication steps. Missing work is returned to the worker instead of immediately reporting success.
- Repeated rejected final claims without successful tool progress stop as incomplete. Invalid or unavailable review cannot confirm completion. Answer-only and explicitly blocked results retain their existing behavior.
- Missing search queries include a valid call example and clarify that `pattern` selects filenames while `query` supplies the literal search text.

The observed 1.0.37 worker made useful GUI changes but reported finished with validation pending, no commit, and a queue-reader import without the actual bridge polling loop. Its unfinished edits are preserved in local commit `0295b75` on `codex/gui-worker-attempt-20261021`; they are not part of this release. Completion review is an LLM evidence check, not an independent execution or guarantee of correctness.

Validation: canonical offline syntax checks and wheel build passed; 1,194 tests passed and one skipped. Focused completion-review tests also passed after tightening evidence formatting. Coverage includes rejection-to-tools recovery, repeated unsupported claims, malformed decisions, unavailable review, blocked-result bypass and actionable search errors.
