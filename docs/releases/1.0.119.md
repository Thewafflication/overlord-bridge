# Overlord 1.0.119

Coding workers retain project-scoped evidence in local SQLite and retrieve it
through memory_search and paged memory_read tools. A small startup index supplies
recent IDs and the model's previous next action. Source hashes, timestamps,
run/action provenance and run-start Git revisions distinguish historical context
from current state. Stored commands are historical; plans are assessments.
Current acceptance and permissions remain authoritative.

Memory survives context trimming, restarts and existing upgrade preservation.
Storage/retrieval are bounded, known secrets are redacted, source permissions
are rechecked and eviction counts are explicit. Recall does not inflate execution
progress or reset completion challenges. Cancellation waits for owned memory I/O.

A controlled restart regression retrieves source, edits, validates and commits
without another model-requested source read. It proves functionality, not a live
delivery-rate gain. Small-context fitting shortens duplicated coaching before
refusing protected context; Groq estimates below protected task evidence can
retry a smaller valid request within the existing retry limit. Owner requirements
and current plans are preserved.

See [project memory](../project-memory.md) for tools, bounds, provenance, freshness,
persistence and measurement limitations.
