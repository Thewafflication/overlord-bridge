# Overlord Bridge 1.0.34

- Added edit_file for exact, single-match replacements in existing UTF-8 project files. Workers can change a small section of a large source file without reproducing it inside a limited model response. Empty replacements support deletion; missing, ambiguous and no-op edits fail without writing. CRLF newline style is retained.
- Edit operations use existing worker path restrictions and free-mode write approval, with before/after previews. The match is revalidated after approval to avoid overwriting content changed while the prompt was pending.
- Worker instructions now prefer targeted edits for existing files and write_file for new files.
- Free tool-enabled provider responses with finish_reason=length are discarded and the pool tries another model. Partial tool calls cannot reach execution through this path.

The observed turn reached its completion checkpoint, continued research, then ended incomplete with another implementation plan and no edits. The tool contract previously required whole-file writes even for the approximately 92 KB bridge source, while the free pool defaults to a 2,048-token response budget. The log did not record provider finish reasons, so truncation is a separately tested failure path rather than a confirmed cause of that turn.

Full offline validation: syntax checks and wheel build passed; 1,173 tests passed and one skipped. New coverage includes a targeted edit in a file larger than 100 KB, CRLF preservation, deletion, ambiguous/stale matches, approval policies and truncated-response fallback. A new live provider turn was not started.
