# 1.0.87

Free project workers now route requests by the planner's task difficulty and
the current phase. The initial planning call requests a structured difficulty
assessment with a reason; it does not add a separate classification request.
Legacy plans without an assessment use a conservative unknown difficulty.

Known GPT-OSS 120B and Nemotron Super/Ultra profiles are preferred for planning,
non-routine work and completion review. Routine execution prefers known smaller
or lightweight profiles. Unrecognized models remain usable between these tiers.
These are conservative preferences rather than measured quality guarantees.

Three consecutive failed actions or an extended-discovery checkpoint escalates
the remaining run. A rejected completion also requests reasoning preference.
Review prefers a different model family among equally ranked models, while
retaining a usable same-model fallback if necessary. Actual acceptance commands
still override a model's completion judgment.

Routing is request-local: concurrent projects cannot alter each other's
difficulty or the foreground chat model selection. Only the existing admitted
free pool is reordered. Provider opt-ins, live zero-price checks, quotas,
cooldowns, capacity waits and cancellation remain in force. Free mode never
escalates to a paid brain. Existing free-tier account configuration requirements
continue to apply.

Worker transcripts record difficulty, phase and escalation; the work log records
the selected model and whether capacity/admission required fallback. Difficulty
is an assessment, not permission to change requirements or weaken validation.
