# Overlord Bridge 1.0.33

- Background workers keep Telegram typing active for their full lifecycle, including model requests and command waits. Completion, cancellation and failure release their typing claim.
- Overlapping foreground turns and workers share the typing loop; one operation ending no longer cancels another operation's indicator.
- Progress message delivery wakes the typing loop immediately, restoring the indicator that Telegram clears when a bot message arrives. See [Telegram sendChatAction](https://core.telegram.org/bots/api#sendchataction).
- Free project workers receive a completion checkpoint after a plain-text ending. The model can continue with tools or explicitly return a final result with outcome finished/blocked. Ignoring the checkpoint reports incomplete. This does not independently verify the truth of a model's explicit completion claim.

The observed restarted turn stopped after 28 research steps with a plan to implement GUI chat, without changing files. Scripted regression coverage replays that ending and verifies the model can return to tools before final completion.

Full offline validation: syntax checks and wheel build passed; 1,165 tests passed and one skipped. Typing lifecycle and refresh use a fake Telegram transport; phone-client visibility still needs verification after updating.
