# 1.0.88

Repeated discovery no longer renews itself merely by recording another plan.
Free workers retain fingerprints of observed tool results across dialogue
trimming. At the existing 12-step discovery checkpoints, the harness also
captures bounded Git change evidence. Three consecutive checkpoints without
new observations or observed repository changes yield a stalled report and
release the worker so other schedules can run. This is not completed work.

Useful new read-only evidence and Git-observed changes from shell commands reset
the check; no artificial edit is required. There is no new total action cap.
The guard does not interrupt an in-flight command. It cannot detect every loop:
novel output can keep a run active, Git evidence is bounded/possibly partial,
and observation history retains up to 4096 fingerprints. Yielding preserves the
checkout and makes no claim that it is clean or unchanged.

Stalled workers save their current plan, recent evidence and unresolved feedback
in the existing report store. Accepted/started events retain this handoff until
the next run can preload it. Handoffs are scoped to the same free worker and
folder, bounded and labelled as prior evidence; current task instructions win.
Provider-capacity stall handoffs benefit from this preservation too.

Free workers also receive verified Git metadata at startup: actual worktree
paths, HEAD, branch or detached state. A worktree directory name is explicitly
distinguished from a branch reference, addressing the observed WCRT loop.
These facts grant no new path permissions and must be refreshed after checkout
or worktree changes. Difficulty escalation remains entirely inside the existing
free model pool.
