# Overlord Bridge 1.0.72

Free-worker planning checkpoints now explicitly request the update_plan function instead of leaving tool choice on auto. The pool validates each planning reply against the same argument and nested plan checks used by workers. Wrong tools, missing or malformed arguments, invalid step statuses and empty assessments trigger model fallback before the worker exhausts its plan-repair attempts. Rejected commands are never executed, and no plan or completed work is invented. If no model supplies a usable response, the run remains incomplete; nonretryable failures do not enter capacity waiting.

The reproduced failure used the previous pool methods with an observed forbidden-action checkpoint reply: the worker stopped incomplete before repairing or publishing. With the repair, the same replay falls back to a second model, repairs a regression, independently validates it, commits only the changed source and pushes to an isolated bare test remote with matching SHA. A live Groq GPT-OSS120B checkpoint also supplied a valid plan and assessment. This repairs the checkpoint protocol; it does not claim unrelated project test failures or remote-access blockers are resolved.
