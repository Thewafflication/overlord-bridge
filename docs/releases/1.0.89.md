# 1.0.89

The repeated-inspection guard now handles the WPM pattern where a fresh-looking
Git result kept renewing a window otherwise dominated by rereading the same
document. Three consecutive 12-step discovery checkpoints with at least half
their observations repeated or failed, without observed repository changes,
yield a stalled result. Mostly new successful evidence or Git-observed changes
reset the check. Newly worded errors and plan updates cannot renew it alone.
There is no new total action cap; read-only work producing new evidence can
continue, and files remain preserved when a run yields.

Stalled responses include the next action from the last recorded plan, labelled
as a worker assessment, and the most repeated tools. Checkpoint logs and terminal
reports expose the counts that caused renewal or yielding. Bounded/partial Git
evidence and finite observation history remain limitations; this does not claim
to detect every loop or prove every reported result is meaningful.

Manual cancellation now preserves the current plan, progress diagnostics, actual
session ID and recent transcript instead of replacing everything with “Stopped
by operator.” Incomplete free runs also save a handoff. Accepted/started events
retain it for the next same-worker, same-folder run, where current instructions
take precedence. No change grants additional permissions or switches free work
to a paid brain.

Regression coverage reproduces eleven repeated reads plus one rotating metadata
result per checkpoint, rotating failed commands, and cancellation during model
continuation. Matching runs yield within 48 action turns in the reproduction;
healthy new evidence and observed source changes continue.
