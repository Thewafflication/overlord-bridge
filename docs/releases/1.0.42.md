# Overlord Bridge 1.0.42

- Reject unknown top-level worker tool argument names and incorrect declared argument types before approval or execution. A misspelled source range now reports accepted parameters instead of silently reading the default page. File, command and plan value/path checks remain in place.
- Advertise exact parameter objects in tool schemas. Runtime keeps the existing cmd command alias.
- Return recoverable errors for malformed formal argument JSON and non-object payloads. Error details and logs name rejected fields/types without echoing their values.

The observed 1.0.41 run accepted a startup plan and made real queue edits, but still sent malformed Python requests. Inspection also found that ignored read parameters could silently change what source was returned. The new boundary makes these tool-contract failures explicit. GUI feature work remains on the local continuation branch, separate from this harness release.

Validation: 201 focused tests passed; full canonical checks pending integration.
