# Overlord Bridge 1.0.57

- Preserve the default installed worker_reports directory across Windows upgrades and remove/reinstall state restoration. Latest worker/session reports, event history and its rotated file now follow the existing persistent-state path alongside configuration and session pins.
- Reject linked worker-report directories/files before recursive copying so state preservation cannot follow a junction or symbolic link into unrelated files. Replaceable virtual environments and live control-service state remain excluded.

This fixes a live evaluation failure: upgrading 1.0.55 to 1.0.56 removed the saved worker report needed to resume its interrupted task. The code fix and tests survived in the project folder, and the worker was recovered using a separately retained session identifier.

Lifecycle regressions cover repeated upgrade/reinstall state copies, updated latest reports, event history and rotation, retained session pins, excluded environment/control files and rejected external links. Fixtures contain synthetic data only.

Validation: all eight lifecycle tests passed. Canonical syntax/inventory, wheel build and full suite passed with 1,324 tests and one skip. The new report-retention regression failed against the old helper before the fix.

Installed Windows verification: the signed package installed successfully and preserved the existing latest worker report and event history byte-for-byte; the finished worker/session mapping remained readable. Windows release CI passed. Linux CI exposed an older hidden-session-pin scan issue; 1.0.58 supplies that follow-up fix without changing this tag.
