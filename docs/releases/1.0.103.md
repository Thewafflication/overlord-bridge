# Overlord 1.0.103

Fix WSP's reproduced commit blocker. The ownership guard treated newlines inside
a quoted commit message as command separators, ran Git under its own temporary
index lock, and produced an opaque lock failure. The worker then proposed stopping
the bridge to remove that supposed stale lock.

Standalone double-quoted literal multiline Git commit messages now pass the ownership check.
On Windows, default execution uses the existing encoded PowerShell mode because
CMD truncates the message body. Expansion-bearing forms and command boundaries
outside the quoted message remain blocked. Approval uses the actual selected
shell, and results disclose the execution mode. Unsupported staging/commit wrappers
receive explicit separate-command guidance without launching Git under the lock.
Lock-inspection results explain the harness-owned lock's lifetime and prohibit
deleting it or stopping processes.

A Git-backed worker regression validates changed source, commits with the full
multiline message, and leaves the pre-existing owner helper untracked. Negative
controls reject injected command boundaries and expansion forms. This verifies
the harness workflow, not a higher live project-delivery rate or project approval
facts. Existing ownership, alternate-index denial and acceptance checks remain.
