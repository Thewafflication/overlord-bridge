# Overlord Bridge 1.0.40

- Preserve initial file hints and handoff context when trimming worker history. Previously the original task survived, but the targeted continuation instructions could be discarded.
- Refresh read/list/search duplicate guards after context trimming so the worker can reread evicted source. Command/write protection remains intact. Real file changes refresh repeated-call counters so reads and validation can be repeated after repairs; identical writes report changed=false and leave the file untouched.
- Add update_plan for bounded, model-maintained next steps and findings. Its latest state survives trimming, without filesystem writes or extra approval. Plan completion flags are assessments and do not replace actual validation evidence or final review.

The observed 1.0.39 run repeatedly lost context, reread the same source, hit duplicate-read guards and restarted discovery without editing. These changes address that recovery loop. GUI feature work remains on the local continuation branch and is not included in this harness release.

Validation: 180 focused tests passed; full canonical checks pending integration.
