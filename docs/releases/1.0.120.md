# Overlord 1.0.120

Worker outcome reports now include explicit `skipped` outcomes and reconcile
retained `started` events with terminal reports. Previously, both skipped work
and starts lacking a terminal report disappeared from outcome accounting.

The new `run_coverage` section reports started, resolved, unresolved and
acceptance-verified attempts in a start-time cohort. A separate list retains
unresolved starts even before the requested `since` cursor. Existing top-level
outcomes still use terminal time; their denominator now includes skips. Compare
historical rates with this definition change in mind.

Joins use worker, project, session and start instant, including resumed sessions
and normalized timezone offsets. Legacy terminal events without a start instant
match the most recent preceding start for that worker/project/session. Missing
session provenance cannot close a different attempt. Rotated journals are read
together. Accepted dispatches are not execution starts.

An unresolved start means no matching terminal report exists in retained
journals. It may be active, lost or affected by journal retention. No crash,
duration, process liveness or successful delivery is inferred. This release
improves measurement; it does not fix the underlying project stalls or prove
increased accepted delivery.
