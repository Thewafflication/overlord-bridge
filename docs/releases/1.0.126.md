# 1.0.126 - retain initial command diagnostics

Worker process capture now keeps bounded beginning and end excerpts of stdout
and stderr. Previously it kept only the tail, so the first compiler error or
build invocation could disappear before the context fitter received the result.
The two raw buffers share the existing four-bytes-per-output-character bound;
both pipes are still drained concurrently. Exit codes, timeout and cleanup
behavior stay intact.

Complete excerpts are redacted before character shortening. When the byte
buffer overflows, partial lines bordering the omitted interval are discarded
to avoid exposing a credential fragment or broken UTF-8 character. Omission
markers distinguish discarded middle bytes/boundary lines from further
character shortening. A single line longer than either byte excerpt may be
entirely omitted; this is bounded diagnostic capture, not a full build archive.

Three new cases fail before repair, including real subprocesses emitting large
stdout/stderr and exiting 9. The repaired capture retains first and last
diagnostics on both streams. A scripted worker receives the initial probe
marker, then edits a real file and validates it. Additional checks cover exact
small-output reconstruction, UTF-8, redaction, memory bounds and timeout cleanup.

Controlled 1,800,045-byte replay: initial diagnostic retention improves from
zero to one, final diagnostic remains present, raw storage remains 96,000 bytes.
This does not establish a live model-quality or accepted-delivery improvement.
