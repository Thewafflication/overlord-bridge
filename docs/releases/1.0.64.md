# Overlord Bridge 1.0.64

Overlord now supports persistent one-time and recurring scheduled tasks from the console and Telegram. Use the new Schedules button or `/schedule help` for commands.

- `/schedule in 30m <task>` schedules a delayed prompt.
- `/schedule at 2026-12-01T09:00:00-06:00 <task>` schedules an explicit time with a UTC offset.
- `/schedule every 24h <task>` repeats at a fixed elapsed interval.
- `/schedule` lists IDs, state and next dispatch time. `pause`, `resume`, `run` and `remove` manage a task by ID.

Schedules survive restarts and `/new`. Due tasks wait for the foreground turn to finish and use the active brain, conversation and existing permissions. Results arrive in ordinary chat. Overlord must be running; overdue tasks run when it is next idle, and recurring schedules skip missed intervals without a burst of repeated prompts. Fixed intervals do not track daylight-saving wall-clock changes.

State is saved atomically before dispatch to prevent automatic duplicate replay after a crash. A crash at that boundary can leave a task marked dispatched without a result; use `run <id>` to retry explicitly. The state reports dispatch, not completion. Invalid storage is preserved and disables scheduling instead of silently discarding tasks. `/stop` interrupts the active turn; pause or remove the schedule to stop future occurrences.

Validation: release version check, syntax/inventory checks and wheel build passed. The final full offline suite passed 1,382 tests with two skips. Seventeen scheduler tests cover persistence, overdue and recurring execution, busy-turn deferral, management commands, invalid times and storage, failed writes, dispatch failures, bridge routing, real asynchronous turn sequencing and watcher recovery/cancellation. An existing subprocess-stop test now waits up to fifteen seconds for startup and reports early tool failures while retaining its process-tree cleanup assertions.
