# Overlord 1.0.90

Free project workers now assess deliverable readiness before project actions.
The plan must identify the actual unfinished requirement, useful outcome,
acceptance check and current evidence. Missing requirements, concrete blockers
and previously completed work yield an incomplete report with a saved handoff.

When more evidence is needed, the worker gets six read-only file discovery
actions followed by a readiness reassessment. Commands, writes and successful
completion are blocked during discovery, and the allowance cannot be renewed.
Ordinary plan updates cannot bypass admission. The terminal `work_readiness`
field records the model's assessment for audits.

This addresses repeated discovery and documentation churn admitted by the old
shape-only plan check. It does not guarantee model judgment or test quality.
Existing owner-defined acceptance checks, permissions, free-model constraints,
schedule inventory, sessions and settings remain in force. See
[deliverable readiness](../deliverable-readiness.md) for behavior and limits.
