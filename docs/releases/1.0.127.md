# 1.0.127 - retain handoffs through startup failures

When a free worker could not record its initial plan, its zero-action terminal
report replaced the preceding unfinished handoff with a null plan and empty
evidence. Subsequent attempts lost the known next action, diagnostic and
completion feedback even though no new work had superseded them.

A failure before both a valid plan and any action now retains the loaded
handoff as a flat object. Current attempt status, timing and activity counters
remain on its own report. The current owner request still takes precedence;
prior evidence remains advisory and must be reconciled with the checkout.
A new valid plan continues to produce a new handoff. Successful completion
still clears unfinished context. No automatic provider retry or acceptance
weakening is introduced.

Two regressions failed before the fix: unavailable pool and invalid startup
plan. Each now retains the plan, diagnostic, step and feedback through two
failed attempts and exposes them to the following worker. Focused handoff
checks: 12 passed. This proves continuity, not provider availability or a live
accepted-delivery improvement. Release/install results are tracked in
../release-automation-2026-11-18.md.
