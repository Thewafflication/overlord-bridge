# Overlord Bridge 1.0.62

Telegram is optional. Missing credentials start the local console; OVERLORD_TELEGRAM_ENABLED=0 disables Telegram while retaining saved credentials, and 1 requires credentials. Existing configured installations keep Telegram enabled. Settings > Integrations adds the enable switch, bot token and owner chat ID (restart required). A failed Telegram startup falls back to the local console rather than ending the bridge.

The console now supports approval decisions, model-authored questions and command options through the existing permission gate and handlers. A durable response queue prevents rapid responses from overwriting each other. Pending prompts are separate from chat and grouped in tabs; stale or repeated responses cannot resolve another request. Responses from either interface clear completed prompts. Disabling Telegram does not weaken approval or off-limits checks.

The GUI gives conversation more space: engine cards and detailed logs are collapsible; a multiline composer supports Enter to send, Shift+Enter for a newline and Ctrl+L to focus. A visible working indicator, model/effort shortcuts and Stop task replace reliance on logs and a prominent whole-service shutdown button. The composer and approval controls reserve their space at the minimum window size, and drafts survive failed queue writes. Existing chat history remains shared.
